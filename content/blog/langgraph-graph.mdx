最初我的 Agent 逻辑是一大段命令式代码：调用模型、看结果、决定下一步、再调用……分支一多，就成了没人敢碰的意大利面。

## 把流程显式化

LangGraph 的核心思想很朴素：把 Agent 建模成一张**状态图**——节点是步骤，边是转移条件，状态在节点间流动。

- 每个节点只关心“给定当前状态，我该做什么”
- 转移逻辑集中在边上，一眼看清所有分支
- 回退、重试、人类介入都变成图里的显式路径

## 为什么更好调试

当某次执行出错，你能精确地看到它走了哪条路径、在哪个节点的状态变成了什么。这比在日志里大海捞针强太多。

> 把控制流从代码里“抽”出来变成数据，是让复杂系统重新变得可理解的经典手法。

图不会让你的 Agent 更聪明，但会让你更有把握地改它。
